# Graphiko & Web App Data Platform

## Introduction

This repository houses a data processing pipeline, analysis environment, and visualization application dedicated to exploring **Topology-Induced Anisotropic Prediction in Semantic Spaces**. Specifically, it analyzes YouTube channel and video data by comparing semantic embedding spaces against topological graph structures (like channel subscription networks).

The core hypothesis is that semantic space around a category optimum may not be isotropic (uniform), and that a topological structure (graph) can help explain why predictive value decays faster in certain semantic directions.

The project is structured into two main components:

### 1. Graphiko (Data Pipeline & Analysis)
Located in `src/Graphiko/`, this is a collection of Jupyter notebooks designed to run on Google Colab. Graphiko is responsible for:
- Fetching and managing channel metadata, video statistics, and semantic embeddings (using Pinecone).
- Constructing topological graphs (e.g., audience overlap via shared subscriptions).
- Constructing semantic distance graphs based on embedding proximity.
- Performing similarity analysis between these graphs (Pearson/Spearman correlation, Mantel tests, QAP-style permutations).
- Persisting canonical matrix artifacts and reduced embeddings to a shared Google Drive for downstream consumption.

### 2. Web App (Visualization)
Located in `webapp/`, this is a modern frontend application built with **React** and **Vite**.
- It consumes the JSON and CSV data artifacts generated by Graphiko.
- Uses **Bulma** for styling and **Recharts** for data visualization.
- Serves to visually interpret the complex multi-dimensional analyses (like 2D clustered video embeddings) produced by the backend notebooks.

## Infrastructure & Data Architecture

The project relies on a multi-database architecture to separate concerns:
- **MongoDB**: Serves as the transactional store (`finder` database). It holds document data such as `videos`, `PublicVideo`, and `TrackedChannel`.
- **InfluxDB**: Serves as the time-series analytical store. Snapshots of video/channel performance are stored in the `channel_metrics` measurement.
- **Pinecone**: Serves as the vector database for storing and retrieving high-dimensional embeddings (e.g., `ChannelDescriptions`, `VideoTitles` namespaces).
- **Google Drive**: Acts as the shared artifact repository. Notebooks mount Drive at `/content/drive/MyDrive/` and read/write matrices and embeddings to directories like `Graphiko/graphs/` and `finder_artifacts/`.

## For Developers and Researchers

- **Graphiko**: To run the analytical pipelines, import the Jupyter notebooks located in `src/Graphiko/` into Google Colab. You will need appropriate credentials for MongoDB, InfluxDB, and Pinecone loaded into your Colab Secrets (`google.colab.userdata`). See `docs/Research.md` and `src/Graphiko/README.md` for methodology and artifact schemas.
- **Web App**: To run the frontend locally:
  ```bash
  cd webapp
  npm install
  npm run dev
  ```
  The local development server will start at `http://localhost:5173`.
- **Documentation**: Further details on development conventions, data pipelines, and research foundations are available in the `docs/` directory.

## Context for Intelligent Agents (AI)

If you are an AI assistant or autonomous agent working in this repository, please adhere to the following context:

- **Artifact Persistence**: Graphiko notebooks save outputs directly to a mounted Google Drive path (e.g., `/content/drive/MyDrive/Graphiko/exports/...`). Do not attempt to read these outputs from the local filesystem unless they have been explicitly synced or downloaded.
- **Matrix Semantics**: Graphiko outputs distance matrices and graphs using a strict `adjacency_matrix.csv` schema with a corresponding `metadata.json`. Pay close attention to `metadata.json` to understand if a matrix represents undirected overlap or directed row-sum normalized distance.
- **Data Naming Conventions**: For analytics and human-readable outputs, always use the canonical `channel_name`. Channel IDs are strictly for secondary metadata lineage.
- **Web App Environment**: The Vite React frontend uses the new JSX transform. Do not explicitly import `React` in `.jsx` files, as it will trigger ESLint errors.
- **Databases**: Mongoose pluralizes collection names (e.g., `PublicVideo` maps to `publicvideos`). InfluxDB uses tags for indexing (like `channelId`) and fields for values (like `views`), requiring a `pivot` operation in Flux queries to reshape the data.
- **Deployment**: The `netlify.toml` file at the root configures frontend deployment. Ensure branch deployments remain explicitly disabled (`ignore = "exit 0"` under `[context.branch-deploy]`).
