# Research

This directory contains notebooks that investigate the relationship between the **geometric structure of channel video embeddings** (20D point clouds) and **natural-language descriptions of those channels** generated by an LLM.

## Motivation

Each YouTube channel in the business cluster is represented by a set of 20-dimensional video embeddings — a *point cloud* in semantic space. Separately, an LLM can summarise what a channel is "about" in prose. The central question is:

> Does the geometric structure of a channel's point cloud correspond to the semantic structure of its prose description?

The notebooks address this in four progressive steps.

---

## Notebook sequence

| # | Notebook | Purpose |
|---|----------|---------|
| 1 | `1.Channel-Descriptions.ipynb` | Generate a prose description for every channel using the **Google Colab native Gemini integration** (no API key required). Results are cached in Drive by channel and as a combined artifact; already-generated descriptions are skipped. |
| 2 | `2.Distance-Comparison.ipynb` | Compare **inter-channel distances** in point-cloud space (centroid, Hausdorff, mean-minimum) against distances in description-embedding space. Report rank-agreement with Spearman ρ, Kendall τ, and top-k neighbourhood overlap. |
| 3 | `3.Shape-vs-Description.ipynb` | Compare the **shape** of each point cloud (volume, concentration, inter-channel overlap) with properties of the channel description after it is split into semantically meaningful segments. Tests three hypotheses: large volume ↔ broad description; concentrated cloud ↔ focused description; overlapping clouds ↔ similar description segments. |
| 4 | `4.Centrality-Ordering.ipynb` | Test whether **central topics appear first** in the description. Ranks point-cloud videos by distance from the channel centroid and ranks description segments by their own centrality, then measures whether the ordering of segments in the original text correlates with their semantic centrality. |

## Coding guidelines

All notebooks follow the conventions in `docs/Graphiko/coding_guidelines.md`:

- Every code cell is preceded by a markdown paragraph describing intent and expected outputs.
- Channel **names** (not opaque IDs) are used in all human-facing outputs.
- Artifacts are written with stable `latest/` pointers.
- Skip-if-exists logic is applied to any LLM-generated artifact so re-running a notebook does not incur unnecessary API calls.
- Each notebook includes a local headless fallback with dummy data so it can be executed in CI without Drive access.
